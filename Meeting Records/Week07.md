In our seventh meeting for the Software Engineer Discipline and Principle course project, we focused on **Think Aloud** and **Heuristic Evaluation** as qualitative evaluation methods. These techniques helped us analyze user interactions and identify usability issues in our project.

## Think Aloud Evaluation & Data Collection
We conducted a **Think Aloud** session to observe user interactions while performing specific tasks. The process included:
- Selecting a **facilitator** and **two observers**.
- Assigning **two short tasks** for the participant to complete.
- Observing and recording user actions and verbalized thoughts.
- Consolidating observer data for analysis.

The collected feedback will help us identify usability issues and improve user experience.

## Heuristic Evaluation & Analysis
A **Heuristic Evaluation** was performed by inviting an external observer to review the game:
- The observer familiarized themselves with the game before assessing usability.
- Key usability issues were recorded based on established heuristics.
- Findings were analyzed as a team to prioritize improvements.

## Key User Feedback
### General Feedback
- **Positive:** The game is engaging and intuitive.
- **Confusion Point:** Some mechanics were difficult to understand without guidance.

### Suggested Improvements
- **Gameplay Instructions:** Add an **introduction page** to explain game mechanics.
- **User Guidance:** Improve feedback on **hidden level unlock conditions** (players need clearer indications).
- **Difficulty Balance:** Implement **difficulty selection** with adjustable speed and enemy behavior.

## Next Steps & Homework
Based on the evaluation, our next steps include:
- Implementing **two difficulty levels** for player selection.
- Enhancing **visual feedback**, including **success screens** and **reset prompts** to improve clarity.
- **Updating our GitHub repository** with evaluation findings and planning a more in-depth user study.
